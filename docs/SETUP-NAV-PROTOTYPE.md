# Setup — Navigation Prototype

Goal: walk on the phone, with headphones, and hear a wall **before** you touch
it. Nothing else. No maze logic, no scanner, no creatures.

Time: about 20 minutes in the editor, then one build to the phone.

> **Fast path.** The whole scene is generated by a menu item:
> **`TheLastCrew → Build Playable Test Scene`**.
> It creates the maze, the player, the camera, the audio listener, the
> footsteps, the wall probes and two landmarks, with every reference already
> wired. Press Play and skip to section 4.
>
> Sections 1–3 below are the same thing done by hand. They are worth reading
> once, because eventually you will want to build a scene that is not this one.

---

## 0. What you need

- Unity project open (`Documents/game`)
- Platform switched to Android
- Headphones
- The placeholder sounds in `Assets/Audio/Placeholder/` — Unity imports them
  automatically. They are synthetic; they exist so you can test tonight.

Optional but recommended: regenerate or replace them later with
`python3 tools/generate_placeholder_audio.py`, or drop your own files in with
the same names.

---

## 1. Build a space worth listening to

The point of this step is not "a maze". It is **variety**: one open area, one
narrow corridor, one dead end. If every direction sounds the same, there is
nothing to learn.

1. Open or create `Assets/Scenes/AudioMaze/AudioMaze.unity`.
2. Delete the default `Main Camera` and `Directional Light` if present
   (the player will bring its own camera).
3. `GameObject → 3D Object → Plane`, rename **Ground**, scale `(5, 1, 5)`.
4. Add four or five cubes as walls:

   | Object | Position | Scale |
   |---|---|---|
   | Wall_A | `(4, 1.5, 0)` | `(0.3, 3, 8)` |
   | Wall_B | `(0, 1.5, 5)` | `(8, 3, 0.3)` |
   | Wall_C | `(-3, 1.5, -2)` | `(0.3, 3, 5)` |
   | Wall_D | `(2, 1.5, -4)` | `(4, 3, 0.3)` |

   With these you get: an open area, a corridor between A and C, and a
   dead-end pocket behind D. Walk it with your eyes closed later and you should
   be able to tell those three apart.

5. Check each wall's `Box Collider` exists (cubes get one by default).

### Optional: put walls on their own layer

Only do this if probe raycasts hit things they shouldn't.

1. `Edit → Project Settings → Tags and Layers → Layers` → add a user layer
   called **Walls**.
2. Select every wall cube → `Layer → Walls`.
3. On `WallProximityAudio` later, set **Wall Mask** to `Walls`.

You can skip this for the first test: a ray that starts inside the player's own
capsule does not hit that capsule, so the player will not hear themselves.

## 2. The player

Hierarchy:

```
Player
└── PlayerCamera
```

### On `Player`

| Component | Settings |
|---|---|
| Transform | position `(0, 1, -3)`, rotation `(0, 0, 0)` |
| Character Controller | Center `(0, 0.9, 0)`, Height `1.8`, Radius `0.3` |
| `TouchInputProvider` | defaults are fine |
| `PlayerMotor` | Input Source → drag **Player** into the slot |
| `FootstepAudio` | Motor → **Player**, Clips → `footstep_01/02/03` |
| `WallProximityAudio` | Rustle Clip → `wall_rustle_loop`, Max Range `5` |
| `SpatialAudioGuard` | Expected Listener → **PlayerCamera** |
| AudioSource | required by `FootstepAudio` — Unity adds it when you add the component |

`PlayerMotor` and `FootstepAudio` both need an `AudioSource` on the same
GameObject. `FootstepAudio` has `[RequireComponent(typeof(AudioSource))]`, so
adding it creates one automatically.

### On `PlayerCamera`

| Component | Settings |
|---|---|
| Transform (local) | position `(0, 1.6, 0)` |
| Camera | defaults |
| Audio Listener | **exactly one in the whole scene** |

## 3. One landmark

Landmarks are how the player knows *where* they are, not just *what is near*.
Without them, every corridor feels identical and navigation becomes exhausting.

1. `GameObject → Create Empty`, name **Landmark_Hum**, position `(6, 1.5, 6)`.
2. Add an `AudioSource`:
   - AudioClip: `landmark_hum_loop`
   - Loop: ✔
   - Play On Awake: ✔
   - Spatial Blend: **1** (3D)
   - Volume: `0.55`
   - Min Distance: `2`
   - Max Distance: `18`
   - Doppler Level: `0`
3. Add a second landmark later at the opposite corner with a *different*
   sound. Two landmarks are the minimum for triangulating a position; one is
   just a directional cue.

## 4. Test in the editor first

Press Play. The mouse is captured; press `Esc` to release it.

| Key | Action |
|---|---|
| `W A S D` | walk |
| `Q` / `E` | turn left / right |
| `C` or `Ctrl` | quiet step (crouch) |

**Pass condition, with your eyes closed:**

- [ ] You hear your own footsteps and they change rhythm when you crouch.
- [ ] Walking toward a wall, the rustle rises *before* you hit it.
- [ ] Turning in place moves the rustle around your head, not in volume only.
- [ ] In the corridor the rustle is on two sides; in the open area it is faint.
- [ ] You can hear the landmark hum behind you when you turn away.

If the rustle sits in the centre of your head instead of to one side, that is a
**stereo problem, not a game problem** — check that the Audio Listener is on the
player camera and that the probe AudioSources have Spatial Blend = 1.

---

## 5. Build to the phone

1. `File → Build Profiles → Android`.
2. Plug in the phone, enable USB debugging, accept the prompt.
3. `Build And Run`.

**On the phone, this is what you are testing** — none of it can be tested in
the editor:

- [ ] The four corners are comfortable to reach while holding the phone in landscape
- [ ] Turning with the top corners feels precise enough to aim your ears
- [ ] Dragging in the middle walks you where you intended
- [ ] Your own footsteps are not clipping or harsh through the phone's DAC
- [ ] You can complete the "find the landmark" task with the screen ignored

---

## 6. When it is wrong, tell me these three things

1. What you expected to hear, and what you actually heard.
2. Whether headphones or speaker.
3. Whether it was the editor or the phone.

Nine times out of ten, "the audio feels wrong" is one of: a second Audio
Listener, Spatial Blend left at 0, or a probe hitting the floor because
`probeHeight` is too low.

---

## What this prototype deliberately does not have

No maze generation, no collision-with-wall sound logic, no scanner, no cooldown,
no menu, no self-voicing, no creatures.

Those all sit on top of one assumption: **a player can hear the shape of a space
and move through it confidently.** If that assumption is false, everything built
on it is wasted work. So we test it first, on the device, with the screen off.
